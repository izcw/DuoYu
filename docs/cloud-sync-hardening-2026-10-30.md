# 多设备同步优化与验证（2026-10-30）

## 合并和离线规则

联网设备先拉取，再提交本地队列，再拉取。离线设备持久保存操作，重连后执行同样流程，最终收敛；不依赖设备时间决定胜负。不同字段自动合并，图标的颜色、文字等子字段也独立合并；相同最终值无需产生冲突。

同字段不同值、布局碰撞、删除与修改冲突保留云端，并保存本机操作供处理。布局按事务整体接受或拒绝，不拆散多选移动。冲突面板左侧显示本机、右侧显示云端，直接复用桌面 LibraryGrid 和 WallpaperSurface。支持切换页面/文件夹、放大浏览，选择应用本机或云端版本，不再显示修改前和逐字段编辑。本机布局优先占位，其余项目按桌面共用规则让位，并将这些位置一并提交。应用前再次检查修订号，云端变化后要求重新确认；处理记录保留。已删除实体不会被旧设备静默复活，明确恢复使用新 ID；固定设置采用显式当前修订号恢复。

无效或超额操作隔离为待处理项，不阻塞后续上传与下载。响应丢失仍按原操作 ID 和原请求重试。数据库恢复工具会轮换数据代次，旧离线队列保留供审阅，不会直接覆盖恢复后的云端。

## 界面和导入

已同步显示 YYYY-MM-DD HH:mm:ss（本机时区）。删除本机数据直接导入空账号、导出冲突副本入口。新增多鱼 JSON 备份文件导入，预览数量后确认，重新映射 ID、增量添加，默认不导入设置；同一文件重复导入受保护。校验格式、网址、父子关系、资源哈希和操作数量，登录凭证及内部同步状态不导入。JSON 备份携带图片以便跨设备导入。

## 图片

壁纸和上传图标使用单独二进制接口上传，SHA-256 去重，业务记录存图片引用。当前文件内容存在 PostgreSQL bytea，账号隔离。客户端 IndexedDB 缓存 Blob，页面使用 Object URL；已上传图片无需每次重复上传。图片下载失败不阻断文字和布局同步，可重试。

Base64 只用于扩展消息桥接和可移植 JSON 文件，不作为云端业务记录或页面图片的常驻格式。Base64 比原二进制约大三分之一，较大图片不适合长期嵌入每次同步的 JSON。后续资源规模增长时可保持哈希引用协议，将存储迁移到私有对象存储并使用受控下载链接。

## 测试及部署

通过本机专用 PostgreSQL 测试库、独立 IndexedDB 客户端验证全部六种两台/三台联网离线组合、重连收敛、幂等重试、冲突处理、错误操作隔离、图片失败重试、JSON 增量导入与凭证排除、数据代次变更保留离线操作。服务端 15 项测试通过。临时 Edge 扩展验证三方手动合并、文件导入及状态时间显示，测试身份由脚本模拟，未发送认证邮件、未修改真实用户数据。

服务端增量迁移已部署，部署前完成加密备份，恢复工具 dry-run 验证 GCM 完整性通过，未执行生产恢复。服务及备份定时器正常。扩展前端需要重新加载新版扩展。

## 边界

自动同步调度依赖打开的新标签页；全部页面关闭时队列保留，下次打开恢复。不是实时协同编辑，通常约 30 秒轮询，聚焦/联网时立即尝试。人工冲突处理无法同时保留同一字段两个相反意图；界面保留历史供选择。图片单个 20MiB、账号附件 100MiB；历史回执和删除标记未自动清理。备份仍在同一服务器，管理员需要安排异地备份及隔离环境完整恢复演练；本次只验证生产备份解密完整性。
